## 계획 모드 수행 시 반영 사항
1. **측정 → 작은 수정 → 확장 순서.** 큰 설계(용법 저장소·통합 리포트·생성 반영·웹 번복)는 앞 단계 결과가 나온 뒤에만 다룬다. 시작 후보는 가장 작은 길: ①활용형 허용 정규식(오탈락 확인된 13개 문형) ②자연문·비문 양방향 테스트를 상시 테스트로 ③판정 상태·이유 기록. 결정 대기 6항목(계획서 §7)은 착수 전에 사용자에게 확인.
2. **웹 검증은 가정하지 않는다.** 기능 설계 전에 해당 가정을 실측으로 확인하고, 실측이 약하면 범위를 줄인다(이번 교훈).
3. **지시를 좁히지 않는다.** 사용자 지침과 다르게 설계하려면 구현 전에 명시적으로 묻는다.
4. **질문은 사용자가 가리킨 층위(운영 파이프라인 vs 감사 작업)로 답한다.**
5. 로그 분석 시 `[검증]` 줄 순서 규칙(위 6)을 적용한다. 코드 변경은 스위치 기본 off·기존 테스트 무수정 통과·양방향 테스트 추가를 원칙으로 한다.
6. 착수 전 정리: PR #21 브랜치에 섞인 진단 프로브 3파일 처리, 10/7(수) 정규 실행 전 PR #21 머지 여부.
